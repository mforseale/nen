# Разработка Nen

## Документация

Перед изменениями ознакомься с [архитектурой](docs/architecture.md) и документом соответствующей части проекта. Архитектурные решения записываются в Markdown в `docs/`. Прежние решения сохраняются; новые явно указывают, какие положения заменяют.

Структура репозитория описана в [repository.md](docs/repository.md), доставка изменений — в [ci-cd-plan.md](docs/ci-cd-plan.md). Документация Next.js для установленной версии доступна в `web/node_modules/next/dist/docs/` после `npm ci`.

## Изменения и проверки

Используй отдельные тестовые базы для проверки API. Перед отправкой изменений выполни относящиеся к ним тесты, frontend lint и production-сборку. Команды приведены в [README](README.md). Изменения схемы оформляются миграциями; обновление production-базы выполняется по [инструкции](docs/database-migrations-and-backups.md).

В Git не добавляются базы, резервные копии, пользовательские файлы, рабочие `.env`, ключи, зависимости и результаты сборки. Примеры настроек должны содержать только несекретные значения.
