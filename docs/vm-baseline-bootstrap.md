## Операция

`scripts/bootstrap-vm-migrations.sh` — однократный переход существующей установки. До остановки API он:

1. Проверяет наличие служб, таймера, БД и старой venv. Читает только значение DATABASE_URL работающего API из его process environment и требует ожидаемый `/var/lib/nen/pact.db`; остальные значения не выводит и не сохраняет. Проверяет health API и proxy frontend.
2. Берёт lock в `/run/nen-db-bootstrap/lock` и извлекает только Git-версию `api/app`, `api/alembic`, `alembic.ini` и `requirements.txt` из текущего commit в новый каталог `/opt/nen-db-tools/<sha>-<suffix>/api`. Код принадлежит root и читается группой `nen`; рабочий `/srv/nen/api` сохраняется.
3. Проверяет Python 3.10, совпадение четырёх core-зависимостей с requirements и `pip check`. Зависимости не переустанавливаются.
4. Выполняет `rehearse-baseline`: online backup рабочей базы, проверенное восстановление в новый файл под `/var/backups/nen/rehearsals/`, регистрацию baseline на копии и сравнение хешей всех исходных строк/BLOB. Источник при репетиции открывается только для чтения. При ошибке приложение продолжает работать.

После успешной репетиции скрипт кратко останавливает `nen-api.service`, создаёт свежую копию перед изменением под SQLite write lock и выполняет `migrate --adopt-existing --baseline-only`. Разрешена только ревизия `20261019_0001`, когда она является head. Этот установщик нельзя случайно использовать для будущих миграций, меняющих схему или данные. Текущие таблицы не пересоздаются; появляется только версия Alembic.

Проверяется `db_admin check`, затем API возвращается и проверяется напрямую и через frontend. При обычной ошибке, INT, TERM или HUP после остановки EXIT trap пытается снова запустить API. При ошибке миграции действует транзакционный rollback; старая база из backup автоматически поверх live не восстанавливается. Жёсткое прекращение процесса/VM требует ручной проверки службы.

Выполнение на VM пока не подтверждено. Первый переход не меняет ExecStart работающего API: старый код остаётся совместимым с добавленной таблицей версии. При последующей выкладке нового кода проверка версии уже будет готова.

Проверка подготовки: локальный unittest обнаружил 80 тестов, 79 прошли, проверка systemd пропущена в Windows и выполняется на Linux CI. Новые сценарии проверяют сохранность BLOB и неизменность исходного файла при репетиции, отказ при несовпадении схемы и запрет будущего head в baseline-only режиме. `pip check`, Bash-синтаксис и actionlint прошли. Само управление службами на production подтверждается только выводом запуска пользователя.

## Запуск пользователем через root SSH

```bash
(
  set -eu
  git -C /root/nen-db-tools pull --ff-only
  bash /root/nen-db-tools/scripts/bootstrap-vm-migrations.sh
)
```

Все снимки и репетиционная база остаются в `/var/backups/nen`; данные не отправляются в GitHub. Установщик не останавливает frontend или Caddy. Новый исходный код сайта этим шагом на production не выкладывается.
